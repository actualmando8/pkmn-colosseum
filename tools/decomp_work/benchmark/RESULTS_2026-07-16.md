# Compile-loop model pilot — 2026-07-16

## Outcome

Kimi K3 successfully participated in the exact-MWCC/objdiff feedback loop. It
produced no improvement or exact match on the initial three-function pilot, but
a later, separate semantic-feedback pilot moved `GStextureLockImage` from a
91.0% baseline to an exact isolated object in two rounds.

This is a small engineering pilot, not a general model leaderboard: K3 was
tested on three functions, Kimi K2.7 Code and a bounded Codex agent on two shared
functions, and no condition used repeated independent trials. The semantic
follow-up used one additional function under a different feedback condition.
It demonstrates that K3 can act on this combined feedback, not that K3 is
generally superior or ready for broad farm deployment.

cross-model comparison as directional.

objdiff, and compact Dolphin-interpreter state mismatches from the pinned
ModernGekko dependency tree. This was a separate condition from the comparison

Round one is an important negative control: a large objdiff improvement did not

## Exploratory diagnostics

Before the retained runs, `fn_80034708` was tried with output caps from 1,024
through 16,384 tokens. K3 used essentially every available completion token for
reasoning and returned no complete final-content function. Approximate API wall
times rose from 31 s at 1,024 tokens to 226 s at 8,192 and 469 s at 16,384.
These schema/debug trials are excluded from the table and any quality claim.

A hardened baseline preflight also excluded two nominal suite entries before
any model request. `HSD_Index2LightID` advertised 99.642860% but recomputed at
99.107140%; `heroMoveSetNeckMode` advertised 94.986000% but recomputed at
94.202896%. Both were removed from `suite_pilot.json` rather than silently
changing the benchmark denominator. A bounded two-candidate Codex diagnostic
on `HSD_Index2LightID` tied the recomputed 99.107140% baseline, but is excluded
from the comparable table because the work-unit metadata was inconsistent.

The `fn_800B7D3C` and K2.7 runs originally compiled C found inside streamed
reasoning when final content was empty. The hardened runner now labels this
explicitly as `reasoning_salvage`, excludes it from primary metrics and primary
feedback, and never persists raw reasoning text.

Direct `deepseek-v4-pro` and `glm-5.2` comparator requests reached their
providers but stopped before inference because those accounts had no spendable
balance/resource package. The configured OpenRouter account also had no
spendable balance. Those are infrastructure failures, not model scores.

## Current-master semantic K3 retest — 2026-07-21

A second bounded current-master run tested `fn_801A6DA0` from clean merge
`76ecf7c4`. The 36-byte pointer-list leaf had an 88.333336% baseline and a
fresh `isolated-equals-full-tu` work unit. Before the API call, the new
`fn_801A6DA0-v1` profile was qualified against pinned ModernGekko
`11237c119a5d8e907a20e9cae1c357df149aaa47`, RecompCore
`1873066167f3d03b39771b547f280d2b970427b6`, and DolRecomp
`a2b02e5a515fc8971cc551ad51c9e26a9815daad`.

The native-original and Dolphin-interpreter lanes agreed on all 1,000 fixtures,
and the incumbent candidate was semantically equal on all 1,000. The corpus
balances null `HSD_MObj*`, null `HSD_TObj*`, valid/null old head, and
valid/non-null old head cases while observing the complete 0x20-byte MObj and
0xAC-byte TObj regions, including both `+0x08` links. A deliberately bad local
archived candidate failed with 1,248 mismatches, including a null-TObj alert and
incorrect link writes. This established that the oracle could distinguish the
known semantic defects before any model spend.

The retained run is
`build/model_benchmark/20260722T112109.830826Z_moonshot_kimi-k3`. Exactly one
K3 round was allowed, with a 4,096-token completion cap and no automatic retry.
It ended with `finish_reason=length`: 4,093 of 4,096 completion
tokens were reasoning tokens, the final response was empty, and no candidate
function could be compiled or sent to the semantic oracle. The provider reported
7,043 prompt tokens and 4,096 completion tokens over 121.574 seconds. At the
published K3 rates used above, the estimated cost is $0.082569. The best score
therefore remains the 88.333336% baseline; there is no source patch, exact result,
or campaign-bankable progress from this call.

This result preserves the one-round stop gate. Even with fully qualified,
high-signal semantic feedback available, maximum-reasoning K3 may exhaust a
small output budget before emitting C. The profile remains useful for future
models or prompting experiments, but K3 should not receive an automatic retry
for this target.

## What the pilot establishes

- The active work-unit generator, exact MWCC command, objdiff scoring, and
  iterative compiler/diff feedback can be composed into a reproducible model
  test.
- K3 was more operationally usable than K2.7 Code on the tiny shared leaf:
  on `OSAllocFromArenaLo`, K3 returned final C in both rounds and completed in
  roughly one third of the API wall time. With one shared function, this is only
  a directional signal.
- All three harnesses converged on the same worse operand/alignment shape for
  `OSAllocFromArenaLo`; none beat the incumbent.
- K3 tied the `fightType…` incumbent after one no-final round; the bounded Codex
  lane found a nonblind 99.0625% lead that still needs normal source-tree and
  full-build validation.
- In a separate one-function semantic condition, K3 converted compact
  behavioral mismatches plus compiler/objdiff feedback into an exact
  `GStextureLockImage` object by round two. This is workflow evidence, not a
  cross-model quality result.
- No benchmark candidate was linked or accepted as campaign progress during
  the initial comparison. The later semantic candidate passed the normal
  source-tree and full-DOL acceptance gates and banked one exact function; its
  surrounding partial translation unit is not newly linkable.

## Next benchmark gate

Before farm deployment, run at least 30 held-out functions stratified by size
and control-flow shape, with three independent attempts per model and separate
single-shot and compile-feedback conditions. Pin source commit, work-unit hash,
tool hashes, prompt, sampling parameters, and attempt budget.

Primary acceptance metrics should be exact matches, compile-at-1, match lift,
integrated object/link success, full-build regressions, wall time, tokens, and
cost. A practical farm gate is at least three exact held-out wins or a
statistically credible match lift without source-policy violations. Comparator
accounts must be funded before the multi-model result can be called general.
