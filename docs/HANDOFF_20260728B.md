## New tool: `find_frame_mismatch.py`

`tools/decomp_work/find_frame_mismatch.py` compares `stwu r1, -N(r1)` and the
`stmw`/`stfd` saved-register spans between target and ours, for every function.
A frame-size mismatch is a **shape** bug, not a register-allocation one, and it
names the problem before you read a diff line. Reuses
`find_reordered_blocks.py`'s `objdiff-cli` extraction — one pass, no rebuild.

**Read the `algn` column, not the frame delta.** The first version ranked purely
by delta and its four highest-confidence hits were all register transliterations
at 4–21% aligned, where no lever helps. It now ranks by gap weighted by
already-aligned fraction and suppresses anything under 50%, turning 431 raw hits
into ~30 actionable ones.

Gotcha: objdiff omits `diff_kind` **entirely** on matching instructions. There
is no `DIFF_NONE` to test for.

## New levers

**1. `volatile` to force a local out of a callee-saved register.** The tell:
retail stores *and reloads* a stack slot where ours keeps a bare register across
calls. Fixed twice:

- `_cameraLoadCameraMatrix` held a float in `f31`; marking that one local
  `volatile` dropped the `stfd f31`/`psq_st f31` pair and shrank the frame
  `0xe0` → `0xd0`. **+3.4pp**
- `fightActionFlowKaisiPre` held a `u8` flag in `r28` that retail keeps at
  `0x8(r1)`. **+1.77pp**

Apply to **only** the local the target actually reloads. Marking a second float
volatile on `_cameraLoadCameraMatrix` lost 2.0pp — retail kept that one in a
register for the call and merely stored it. And **plain `u8` without `volatile`
scored below the original** (83.90 vs 84.95): the narrow type changes the
compares without forcing memory, so it pays the cost and gains nothing.

**2. Duplicate block-scope local sets inflate the frame.** The same
`f32 x, z, w, h;` declared in two separate blocks got two sets of slots —
exactly the `0x20` of extra frame. Retail shares one set at function scope.

**3. Loop-shaped table scan.** When the target has a live `addi rX, rX, <stride>`
mid-scan but ours folded the second group into constant offsets, rewrite the
unrolled groups as a small `for` loop — MWCC unrolls it and *keeps* the pointer
increment. **+6.7pp** on `fn_80030574`. Re-reading the scan key **inside the
loop body** adds **+2.7pp**; the identical re-read placed *between* straight-line
groups is an exact no-op because MWCC CSEs it away.

**4. An anonymous sdata2 literal is a checkable mismatch.** Retail loading a
*named* `lbl_*@sda21` where we load `@NNN@sda21` means retail's source
referenced a named global, not a literal. On `fn_801985E0` the constant was
already defined in the repo as `SDATA2 const f32 lbl_8047DA14 = 1.0f`.
**+1.62pp.** Look it up in `config/GC6E01/symbols.txt` and confirm the value
before substituting.

**5. De-hoist derived values.** Our Ghidra-derived source groups and hoists
where retail computes at each use. `pokemonCreateRndFit` hoisted `(s8)` casts of
params into locals; retail keeps raw `s32` params and re-casts per site.
**+4.07pp.**

## Everything is per-*site*. This is the dominant lesson.

Not per-function — per call site. Six instances this session:

- `s8` vs `s32` for a local split **inside one function**: the helper's wanted
  `s8` (+0.6pp), the caller's wanted `s32` (making it `s8` cost 1.5pp).
- `fn_800F6D18`: caching `lbl_80271068` won +4.6pp while `lbl_80478B00` needed
  to be **re-read** for +2.3pp.
- The `lbl_8047DA14` substitution won +1.62pp on `fn_801985E0` and **lost**
  0.31pp on `fn_80198B20`, the adjacent function in the same file.
- The group-dispatch goto transcription won on `fn_80030A44` (+3.1) and
  `fn_80031648` (+2.1) and **lost 3.5pp on `fn_80030F0C`** — whose retail CFG I
  pulled from the asm and confirmed is *byte-identical* in shape. Same source
  change, same target shape, opposite sign.

Treat "identical code elsewhere" as a hypothesis to measure, never a batch to
apply.

## Compiler-version sweep on `fn_8001F304` — negative result

Its prologue *form* differs (retail `stwu`/`mflr`/`stw`, ours
`mflr`/`stw r0, 0x4(r1)`/`stwu`), which reads as a version tell, and the unit is
pinned to `GC/1.2.5n`. Swept: `GC/1.2.5` 71.29%, `GC/1.2.5n` 70.76% (current),
`GC/1.3` and `GC/1.3.2` both 63.82%. **A 0.5pp wiggle is not evidence** —
genuine mis-versioning showed 30pp jumps on the MSL units — and the prologue
mismatch persists either way. `configure.py` left alone. The real problem there
is `0x48` of extra frame.

## Addendum 2 — the 96-99.9% near-match band is mostly a dead end

Written after working it deliberately. **State at this point: fuzzy 75.02512%,
matched functions 6584/8603, PRs #504-#518 merged.**

### One match came out of it

`GSmodelSetTexAnimIndex` 96.77% -> **100%** (#518), matched functions
6583 -> 6584. The file already carried
`model->tex_anim_type = model->tex_anim_type;` -- a previous agent had spotted
retail's redundant load/store and written a self-assignment. **MWCC elides a
self-assignment written adjacently**, so that line emitted nothing and the gap
stayed. Retail loads the field *before* the jobj/child block and stores it back
*after*; putting real code between the two halves via a temp makes it survive.

Generalisable: a self-assignment that produces no instructions is a dead line,
not a fix. If retail has the load/store pair, the halves need real code between
them.

### Then seven consecutive failures

I picked one function from each distinct signature class in the band. All seven
lost or were flat:

| fn | signature | attempted | result |
|---|---|---|---|
| `menuSubGetPokemonSexForFightDisp` | retail unfused `clrlwi`+`cmplwi`, we fuse to `clrlwi.` | u32 temp to break the fusion | flat 97.94 |
| `fn_8021A478` | ours has an extra `stw` to the script PC | remove the duplicate | 99.33 -> 98.62 |
| `fn_80165FDC` | retail fuses `mr.`, we emit `mr` + `cmpwi` | `#pragma peephole on` | 96.25 -> **63.93** |
| `fn_8006AE18` | two instructions swapped around a call | (none -- scheduler) | not source-reachable |
| `fn_80266250` | mask at assignment vs retail's mask at use | widen to u32, `(u8)` at each use | 97.69 -> 88.27 |
| `fn_80222BD8` | retail has an intermediate store we lack | force it with a volatile write | 96.30 -> 92.41 |
| `C_MTXLightFrustum` | `fmuls` operand order reversed | swap source operands | no change |
| `fn_800D5504` / `TRKDoSetOption` | retail `addi rD,rS,0` where we emit `mr` | `#pragma peephole off` | 98.82 -> 90.98 |

**Why:** the diffs in this band are overwhelmingly register allocation,
instruction scheduling and peephole fusion -- compiler-internal decisions with
no source handle. `GSmodelSetTexAnimIndex` matched because its three
instructions came from a genuinely missing *source construct*. That is rarer
than the surface pattern suggests, and a filter that selects "non-register
diffs" does not distinguish the two.

**Recommendation:** do not mine this band by diff-shape. The frame-mismatch list
(~30 above 50% aligned) and the reorder detector stay better grounded, because
they point at source *shape* rather than allocator outcomes.

### Two specific facts worth not rediscovering

**Duplicated stores in `fight_range_80211A00.c` are deliberate and correct.**
Both `fn_8021A338` and `fn_8021A478` write a global twice where retail writes
once. Removing the duplicate loses ~0.7pp in *both*. They read like bugs; they
are measured hacks. Restored both. Before "fixing" a redundant-looking store in
that file, measure it.

**`#pragma peephole off` is load-bearing where it already appears.**
`fn_80165FDC` drops 32pp if flipped to `on`, even though retail shows the fused
`mr.` that peephole-on would produce. Retail's fused form is reachable some
other way, not by the pragma.

### New tool: `find_field_mismatch.py` (#517)

Hunts *correctness* bugs rather than score: same-site memory accesses whose
displacement or width differs. It found the `fn_80044378` wrong-field bug
(`sprite->messageId` at +0x4c where retail reads the `s16 eventId` at +6, #516)
-- worth 0.004pp, so no gap-ranked tool would ever surface it.

Most of its hits are **not** bugs; the docstring lists the false-positive classes
found on the first run (different base pointer, pointer-advance vs indexed
access, swapped switch arm). Confirm the base register holds the same thing
before concluding anything.
