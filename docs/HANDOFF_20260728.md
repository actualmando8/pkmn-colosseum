## The lever that mattered most: transcribe retail's CFG as gotos

This is new and it is worth reaching for early.

When the target asm shows **all the comparisons up front and the assignment
bodies out of line**, MWCC did not generate that from an `if / else if / else`
chain. A plain chain puts each body inline right after its test. Retail's shape
looks like this (`evolutionWazaLearn`, classifying a yes/no result):

```
cmpwi r27, 0x1
beq   -> body_1
bge   -> body_2
cmpwi r27, 0x0
bge   -> body_0
b     -> body_2
body_0: li r0, 0x0 ; b join
body_1: li r0, 0x1 ; b join
body_2: li r0, 0x2
join:
```

Note the bodies sit in memory in **value order 0, 1, 2**, which no source
ordering of a chain reproduces. Writing it as a literal goto transcription —
tests in retail's order, labelled bodies in retail's memory order — matched it:

```c
if (cVar5 == 1) goto one;
if (cVar5 >= 1) goto two;
if (-1 < cVar5) goto zero;
goto two;
zero: iVar1 = 0; goto done;
one:  iVar1 = 1; goto done;
two:  iVar1 = 2;
done: ;
```

**Try the transcription before trying to guess a natural spelling.** On
`evolutionWazaLearn` I burned two builds on if/else-chain variants first and
*both scored below the chain they were replacing* (94.14 → 92.25 and → 93.18);
the goto form then went to 97.80. Same story on `selectLetter`: +5.7pp.

Reading the branch targets out of the real `.s` file is what makes this work —
`fdiff.py`'s `<t>` placeholders hide which block each branch goes to. Use:

```
F=build/GC6E01/asm/game/<unit>.s   # or any lane worktree's copy
sed -n "$(grep -n '^.fn NAME' $F|cut -d: -f1),$(grep -n '^.endfn NAME' $F|cut -d: -f1)p" $F \
  | grep -n 'cmpwi\|^\.L\|b[a-z]* \.L'
```

## Switch-arm order is recoverable from the target asm

`selectLetter` has a 7-way switch. Retail's case bodies sit at known addresses,
so the **source arm order can be read off directly** — sort the case labels by
the address each dispatch branch targets. Retail's order was `1/2, 4, 5, 3, 0,
default`; ours was `0, default, 1/2, 3, 4, 5`. Reordering the arms to match was
**+11.5pp** on its own.

Two cautions, both measured:

- The `case 0:` → `default:` fall-through must stay adjacent and in that order.
- Do **not** also try to make the dispatch *tree* match by adjusting the case
  set. Retail pivots on 3/0/5/1 where we pivot on 4/0/3/6, which tempted me to
  drop the explicit `case 6:` so 6 folds into `default`. It lost both before the
  reorder (61.13 → 60.39) and after it (72.58 → 71.94).

## Other things that worked

- **Split a combined if/else into one per call.** `evolutionWazaLearn` had
  `if (x) { open; read; close; } else { open; read; close; }`; retail has three
  separate `if (x)` tests. This was the single biggest fix of the session
  (43 → 92%).
- **Out-of-line error arm plus a `>=` that reuses the cr.** `fn_800F8268`: the
  `ax == -1` body belongs *after* the common path, and retail tests `>= -1`, not
  `>= 0`, reusing the cr from the `== -1` compare. +36.3pp.
- **Check the frame size.** `fn_800F8268`'s scratch buffer was declared `0x50`
  when retail's whole frame is `0x50`; the real buffer is `0x38`. Cheap and
  mechanical — compare `stwu r1, -N(r1)` before anything else.
- **`do/while` rather than `for`** when retail has no entry branch to the
  condition.
- **Watch for accidental signed division.** `selectLetter` had
  `array[byte_off / 2]` where `byte_off = idx * 2`; the divide is *signed*, so
  it cost a `srawi`/`addze`/`slwi` sequence at both use sites. `array[idx]` is
  +2.6pp.
- **Declaring a callee `int` rather than `s8`** moved the `extsb` to the call
  site, where retail has it (+1.5pp). Counter-intuitive: the *implicitly-int*
  callee in the same function was already producing retail's `extsb`, and the
  explicitly-`s8` one was not.

## Things that looked right and lost — do not re-try

Each of these is directly supported by the target asm and still cost score.

| Change | Function | Result |
|---|---|---|
| `#pragma peephole off` | `fn_800F8268` | 46.16 → 42.68 before the restructure, 82.62 → 78.96 after. Retail's un-peepholed `bne L; b join` pairs are visible in the asm, but turning the pragma off costs more elsewhere in the function than those pairs are worth. |
| Drop explicit `case 6:` | `selectLetter` | −0.7pp both before and after the arm reorder |
| Split `case 1: case 2:` into two arms with identical bodies | `selectLetter` | 75.17 → 61.82. Retail has two `li r4, 1` blocks converging, but MWCC will not tail-merge the duplicate. |
| Remove `r31 = 0` on a path where retail has no such store | `selectLetter` | −1.8pp |
| `int cVar5` + explicit `(s8)` casts | `evolutionWazaLearn` | 97.83 → 97.27 |
| `count` as `u32` rather than `u16` to drop the `clrlwi` blocking `bdnz` | `fn_800F6D18` | 59.39 → 58.60 |
| Byte-offset induction in the inner search loop | `fn_800F6D18` | −1.6pp with count re-read, −1.0pp with it cached — even though retail plainly uses a byte offset and `mtctr` there |

The pattern: **retail's asm tells you the target, not the source that produces
it.** Measure every hypothesis separately. The handoff's "targeted edits beat
rewrites" rule held all session.

## Global-address caching cuts both ways *within one function*

**+2.3pp**. Test each global separately, in both directions.

## Reminder on the CI gate

I rebuilt the `origin/master` baseline worktree **before every one of the three
PRs**, because master moved each time. A stale baseline silently compares your
branch against an older master and will not catch a regression against the
current one. Provision `orig/` as real directories with a **file-level** symlink
for `main.dol`, and never seed the worktree from an existing `build/`.
